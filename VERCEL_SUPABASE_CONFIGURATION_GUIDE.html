01

Commit and push the implementation

Publish the verified local code before testing platform integrations.

Push the implementation to the GitHub repository connected to the Vercel dzrzvd project. A push to main should create a new production deployment automatically.

  • Review the local changes and confirm that only intended files are included.
  • Commit the catalog, admin, API, migration, test, and configuration files.
  • Push the commit to GitHub main.
  • Confirm that Vercel starts and completes a new production deployment.
i

The existing public Home, About, Location, Header, and Footer files were intentionally left unchanged. The catalog is a dedicated /products experience.

02

Verify www.dzrzvd.com.tw

The domain is connected; verify it remains healthy before registering production callbacks.

  • www.dzrzvd.com.tw resolves to a Vercel DNS target.
  • The HTTPS request returns HTTP 200 with a Vercel response header.
  • The page content matches https://dzrzvd.vercel.app.
  • Keep the domain assigned to the production deployment in Vercel.
!

The custom domain is ready for production callback configuration. Use https://www.dzrzvd.com.tw consistently for Supabase Auth and the Shopee authorization callback.

03

Create Supabase resources through Vercel

Use separate projects so previews can never write to production data.

Supabase resource Vercel scope Scope marker Purpose
dzrzvd-staging Preview + Development nonproduction Migration, authentication, and dry-sync verification.
dzrzvd-production Production only production Public catalog and daily synchronization.
  1. Open Supabase in the Vercel Marketplace .
  2. Click Install and select the weizzz team.
  3. Create dzrzvd-staging first.
  4. Choose Singapore as the database region to align with Vercel sin1.
  5. Connect staging to the dzrzvd Preview and Development environments.
  6. After staging verification, create production and connect it only to Production.

Variables provided by the Marketplace integration

Verify that Vercel automatically adds at least these keys:

Database

  • POSTGRES_URL
  • POSTGRES_URL_NON_POOLING

Supabase Auth

  • SUPABASE_URL
  • SUPABASE_PUBLISHABLE_KEY
  • NEXT_PUBLIC_SUPABASE_URL
  • NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
!

Never copy SUPABASE_SECRET_KEY, a database password, the Shopee Partner Key, or either generated secret into a NEXT_PUBLIC_ variable. Public variables are included in the browser bundle.

04

Configure Vercel environment variables

Add custom values after the Supabase integration has injected its keys.

Production only 
SUPABASE_PROJECT_ENV=production

SHOPEE_PARTNER_ID=<Shopee Partner ID>
SHOPEE_PARTNER_KEY=<Shopee Partner Key>
SHOPEE_API_BASE_URL=https://partner.shopeemobile.com
SHOPEE_AUTH_BASE_URL=https://open.shopee.com/auth
SHOPEE_REDIRECT_URL=https://www.dzrzvd.com.tw/api/shopee/auth/callback

SHOPEE_TOKEN_ENCRYPTION_KEY=<32-byte base64 key>
CRON_SECRET=<separate high-entropy secret>
Preview and Development 
SUPABASE_PROJECT_ENV=nonproduction

Use distinct Shopee, encryption, and cron values if synchronization is enabled in staging. Leaving Shopee variables unset keeps synchronization disabled while database and Auth behavior are tested.

Safe secret generation on Windows

These PowerShell commands place a value on the clipboard without printing it in terminal output. Paste each result directly into the matching sensitive Vercel variable.

Shopee token encryption key 
[Convert]::ToBase64String(
  [Security.Cryptography.RandomNumberGenerator]::GetBytes(32)
) | Set-Clipboard
Cron secret 
[Convert]::ToHexString(
  [Security.Cryptography.RandomNumberGenerator]::GetBytes(32)
).ToLowerInvariant() | Set-Clipboard
!

The application enforces environment isolation. Production Vercel rejects nonproduction Supabase, and Preview/Development reject production Supabase.

05

Apply the database migration

Validate staging first, then repeat the same migration in production.

Staging

npx supabase login
npx supabase link --project-ref <STAGING_PROJECT_REF>
npx supabase db push --dry-run
npm run db:push

Production, after staging passes

npx supabase link --project-ref <PRODUCTION_PROJECT_REF>
npx supabase db push --dry-run
npm run db:push

The migration creates the protected catalog and app_private schemas, product and category storage, synchronization history, row leases, operator authorization, and product overrides.

!

Do not create or modify these tables manually in the remote Table Editor. Keep schema changes in supabase/migrations so Supabase migration history and Git remain synchronized.

06

Configure Supabase Auth and operator access

Set trusted callbacks, create a password user, and grant the operator role.

Production URL configuration

In Supabase, open Authentication → URL Configuration.

Site URL
https://www.dzrzvd.com.tw

Redirect URLs
https://www.dzrzvd.com.tw/auth/callback
http://localhost:3000/auth/callback

Optional preview URL

https://*-weizzz.vercel.app/**

Create the operator

  1. Open Authentication → Users.
  2. Choose Add user → Create new user.
  3. Enter the operator email and a strong, unique password.
  4. Confirm the email and copy the generated user UUID.
  5. Open the Supabase SQL Editor and run the authorization statement below.
insert into app_private.app_admin (user_id, role, active)
values ('<USER_UUID>', 'operator', true)
on conflict (user_id)
do update set role = 'operator', active = true;
i

Use Create new user rather than email invitation for the first operator. The current admin interface supports email/password login but does not yet provide a set-password screen for invited users.

07

Authorize Shopee and run the first synchronization

Complete provider authorization only after production callbacks work.

  1. Register this exact redirect URL in the Shopee Open Platform application: https://www.dzrzvd.com.tw/api/shopee/auth/callback.
  2. Redeploy production after all Vercel environment variables are present.
  3. Open https://www.dzrzvd.com.tw/admin/login.
  4. Sign in with the Supabase operator email and password.
  5. Open /admin/shopee-catalog.
  6. Connect and authorize the Shopee shop.
  7. Run a dry synchronization and review counts and warnings.
  8. Run the full synchronization only after the dry run is correct.

Only active, in-stock products whose names contain DZRZVD or 杜戛地 are published. Products are organized by Shopee marketplace category, and card links open the original Shopee listing in a new tab.

↻

Vercel Cron runs the synchronization at 18:00 UTC, which is 02:00 Asia/Taipei. Cron invokes only the production deployment and authenticates with CRON_SECRET.

08

Production verification checklist

Do not consider setup complete until the complete data path succeeds.

Application

  • Production deployment is READY.
  • Custom domain has valid SSL.
  • /products loads without setup errors.
  • Category pages render correctly.
  • Product cards open Shopee in a new tab.

Operations

  • Operator login succeeds.
  • Unauthorized users cannot open the admin page.
  • Shopee authorization succeeds.
  • Dry sync reports sensible counts.
  • Full sync stores visible products.
  • Cron appears on the production deployment.
